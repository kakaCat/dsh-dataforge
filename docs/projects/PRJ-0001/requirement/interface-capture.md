## 1. 背景与业务定位

最终产品是一条流水线：**采集 → 编排（DAG）→ 探索执行 → 结晶 → 复跑**，目标是"自动测试一个网站的一连串接口，最终完成业务流程任务"。

本功能是流水线的第一段，也是唯一从零到一的部件：后续编排/执行/复跑的一切原料都来自采集产出的**接口库**。没有采集，后面四段无米下锅；采集本身可独立验收（给定页面 → 产出接口文档），不依赖后续阶段。

**一句话业务定义**：用户在采集页给一个页面地址，系统自动把该页面触发的接口全部抓下来，把**入参和出参整理成接口文档**，连同页面与接口的关系一起持久化入库。

## 2. 业务目标与价值

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 用户无需懂抓包、无需对话指令，在采集页输入 URL 点一下即可采集 | 采集页端到端跑通：输入 → 采集 → 看到该页接口文档 |
| G2 | 产出物是**接口文档**，不是原始抓包日志 | 每个接口一张卡：标识 + 入参文档 + 出参文档，可直接阅读 |
| G3 | 页面与接口的关系完整保存，支持"n:n + 入参差异"的真实形态 | 关系表可追溯：哪个页面、调了哪个接口、用的什么入参 |
| G4 | 接口原料结构化沉淀，供后续编排消费 | 卡片含 URL 模板 + 字段模板 + 变量角色标注 |
| G5 | 登录态可复跑 | 凭证（cookie/token/localStorage）的下发与存放位置被完整记录 |
| G6 | 全程可观测、可审计、可迁移 | 状态可轮询；NDJSON 审计流即写即落盘；SQLite 单文件拷贝即迁移 |

**商业价值**：把"人工抓包 + 人工整理接口文档"的数小时工作压缩为「输一个 URL、点一次按钮」；且产出既是人可读的接口文档，又是机器可消费的结构化卡片。

## 3. 角色与使用场景

| 角色 | 说明 |
|---|---|
| 业务用户（人） | **在面板「采集」页输入 URL、点击「采集」发起任务**；查看实时进度与接口文档；对写操作做确认决策 |
| 对话 agent（AI） | 辅助角色：可代用户发起采集；仅在 `action` 型里驾驶浏览器；可读回产物并用自然语言转述 |
| 采集 worker（插件进程内） | 无智能执行体：起浏览器、旁路网络、归一化、落库 |

**典型场景**：

1. **S1 页面接口采集（第一期主线）**：用户在采集页 URL 输入框填入页面地址，点击「采集」→ 系统采集该页全部接口并生成接口文档，采集页实时显示进度与结果。
2. **S2 全站接口盘点**："把这个系统整站的接口都采下来" → `site_crawl`（BFS 逐页爬行，跨页归并）。
3. **S3 采写操作接口**："帮我采'创建采购申请'这条链路涉及的接口" → `action`（agent 模拟真实 UI 操作，含提交类写操作，须用户显式确认）。
4. **S4 事后审查**：用户在「采集运行 / 接口库」标签页回看历史运行与接口文档，或让 agent 取回分析。

## 4. 采集机制（用什么采、要不要 agent）

### 4.1 机制

采集 = **Playwright 驱动本机系统 Chrome（无头）+ 浏览器层网络事件旁路**：

1. 用 `playwright-core` 起系统 Chrome（`channel: 'chrome'`，免下载浏览器），无头模式 + 基础反检测参数。
2. 在页面挂 `response` 事件旁路：**只收 XHR/fetch 资源型请求**，静态资源（js/css/img/woff 等）全部滤掉。监听发生在浏览器层，**不向页面注入脚本**，页面无感知。
3. 每个接口采到：请求侧（URL、method、请求头、**请求体**）、响应侧（状态码、content-type、JSON 响应体全文）、归属（触发它的页面 URL + 时间戳）。
4. 体量保护：请求体/响应体超上限（默认 256KB）不挂正文、如实标 `truncated`；大体落文件、库存指针。
5. 凭证不走网络旁路：采集收口时从浏览器上下文收割 cookie 全量入库，原文只存本地 SQLite。

### 4.2 要不要 agent

**采集机制本身永远不需要 agent。** 抓接口、出入参、凭证、归一化、落库全是 worker 的确定性逻辑。

| 路径 | 任务型 | agent 的角色 |
|---|---|---|
| 自治路径 | `single_page`（第一期主线）、`site_crawl` | **无**。点「采集」后 worker 全自动跑完，无任何 LLM 参与 |
| 驱动路径 | `action` | agent 只做"司机"：看页面快照、决定点哪填什么；执行与采集仍由 worker 完成 |

这条分工是刻意的：智能可插拔，采集机制稳定可测（除 e2e 门外全部测试零真浏览器、零 LLM）。

## 5. 业务概念模型

| 概念 | 标识 | 定义 | 关键属性 |
|---|---|---|---|
| **采集运行 / 采集包** | `cap_xxx` | 一次采集任务的全部产物归档单元；全局独立，不绑定项目 | 任务型、入口 URL、状态机、统计（页数/请求数/卡数/凭证数） |
| **页面** | `pg_xxx` | 采集访问过的页面 | URL、深度、状态（ok / error / skipped-external） |
| **原始请求样本** | `sm_xxx` | 一次 XHR/fetch 请求的完整厚数据留档（**第一层留档**） | 出入参头/体、状态码、截断标记；大体落文件、库存指针 |
| **接口卡片** | `card_xxx` | 一个接口的归一化定义，**即接口文档的内容载体**（**第二层留档**） | URL 模板、方法、请求头契约、**鉴权标志**、入参文档、出参文档、样本数 |
| **页面-接口调用关系** | — | 页面与接口的 **n:n 关联**，及每次调用的入参形态 | pageId × cardId × 入参指纹（见 §6.2） |
| **凭证事件** | — | cookie / token / localStorage 的下发与写入记录 | 种类、下发来源、名称、值（仅本地库存，不出壳） |
| **登录会话** | — | 站点级登录态（cookie jar 按 origin） | 供同域复用 |
| **浏览器会话** | `bs_xxx` | agent 驱动模式下的常驻浏览器句柄 | 绑定 captureId 时旁路样本桥接入库 |

**运行状态机**：`running → done | failed | cancelled`（cancel 幂等收口，落盘为准）。

**字段角色（role）四值**：`constant`（常量）/ `input`（外部入参，多次调用值会变）/ `chain`（链上生成值，来自前序接口响应）/ `credential`（凭证注入）。标注三来源：自动 diff、agent 语义标注、人工点改（后两者本期部分落地，见 §11）。

## 6. 总体业务流程（第一期）

**第一期主线**：用户在采集页输 URL、点「采集」→ 打开页面采接口 → 出入参整理成接口文档 → 接口/页面/关系入库 → 采集页实时展示。

发起入口以**面板采集页为主**（用户直接操作，不经过 agent 对话）；agent 工具面（`dataforge_capture`）保留为辅助入口。两条入口汇入同一条流水线、同一套闸门与数据模型。

```
【面板·采集页】URL 输入框 + 「采集」按钮
  │  （agent 对话入口 dataforge_capture 走同一闸门）
  ▼
闸门：URL 合法性 → 任务型合法性 →（仅 action）写操作确认
  ▼
打开页面（无头 Chrome），等待网络 idle + 稳定窗口
  ▼
捕获该页触发的全部 XHR/fetch ──────────────→ 样本层：每次请求一条完整出入参留档
  ▼
归一化成接口卡片（= 接口文档内容载体）：
  · 接口标识：method + URL 模板（路径参数抽 {p}，query 滤易变键）
  · 入参文档：字段名 / 类型 / 示例值 / 角色（const|input|chain|credential）
  · 出参文档：字段名 / 类型 / 示例值 + 业务 code 位置探测
  ▼
建立并保存 页面 ↔ 接口 的 n:n 关系（见 §6.2）
  ▼
持久化：SQLite（runs / pages / samples / cards / page_card_relations / credentials）
  ▼
展示与取回：采集页实时进度与接口文档 / capture_status / capture_result / 接口库页
```

第一期的交付物以「**页面 → 该页接口清单 → 每个接口的出入参文档**」为验收单元；`site_crawl` 与 `action` 是同一主线的扩展入口——采到的接口同样归并进卡片、同样落关系，不改变数据模型。

### 6.1 采集入口形态

| 入口 | 输入 | 行为 | 发起方式 |
|---|---|---|---|
| `single_page`（第一期主线） | 页面地址 | 打开页面，等网络 idle + 稳定窗口，捕获全部 XHR/fetch 并文档化 | **面板采集页（URL 输入框 + 采集按钮）**；agent 工具面辅助 |
| `site_crawl` | 入口地址 | 同域 BFS 逐页爬行（默认深 3 / 50 页上限），每页走同一采集与关系落库 | agent 工具面（后台 job） |
| `action` | 页面地址 + 任务描述 | agent 模拟一段 UI 操作（含写操作，须用户确认），全程捕获 | agent 驱动（会话原语） |

### 6.2 页面 ↔ 接口：n:n 关系（核心建模规则）

页面和接口之间**不是**简单的"接口属于页面"：

- **一个页面调多个接口**：页面的接口清单 = 关系表里该页的所有关系行。
- **一个接口被多个页面调用**：同一接口卡挂在多个页面下（跨页复用），接口卡不重复建。
- **同一接口的区别可能是入参不同**：如 `/api/list` 在 A 页传 `{type:1}`、在 B 页传 `{type:2}`——URL 相同、入参不同，是**同一接口的两种调用形态**，不能合并成一笔，也不能拆成两个接口。

关系模型：

```
pages ──< page_card_relations >── interface_cards
              │
              └─ 每条关系行记录：pageId × cardId × 入参指纹（params_fingerprint）
                 + 首次/最近观测时间、样本计数
```

规则：

1. **是不是同一个接口**由归并键决定：`method + URL 模板`（与入参无关）。
2. **是哪种调用形态**由入参指纹区分：对归一化后的 query + 请求体（键排序、滤易变键）做稳定哈希；指纹不同 → 同一卡片下新增一条关系行。
3. **接口文档在卡上沉淀并集**：同一接口的多种调用形态，其入参字段做并集合并进卡的入参模板；形态间值会变（或有无不同）的字段标 `input`，恒定的标 `constant`（单形态保留「未验证」旗标）。
4. **出参文档同理**：同接口不同入参导致的出参结构差异，在卡的出参模板上做字段并集与角色标注。
5. 追溯路径：关系行 → 该形态下的原始样本（样本层厚数据随时可回查）。

### 6.3 出入参文档化要求

接口卡片必须达到"可直接当接口文档读"的程度：

| 要素 | 要求 |
|---|---|
| 接口标识 | method + URL 模板（路径参数抽 `{p}`），可附语义化名称 |
| 请求头契约 | content-type、accept 与业务自定义头（`x-*` 等）纳入文档：`location='header'`，照常做角色标注；**凭证类头（cookie / authorization / proxy-authorization / set-cookie）只记名称与 `credential` 角色，值永不入卡、永不出壳** |
| 鉴权标志 | 显式回答"这个接口要不要 token"：`authType` = `none` / `token-header`（Authorization 头）/ `token-param`（query 或 body 里的 token 类字段）/ `cookie-session`（无 token 但依赖登录态 cookie）/ `unknown`（样本不足，诚实标注）；附**探测证据**（哪个头/字段触发的，只记名称）与凭证来源指向（credential_events，供复跑换票） |
| 入参 | 字段名、类型、示例值、角色（常量/入参/链值/凭证）、所在位置（path/query/header/body） |
| 出参 | 字段名、类型、示例值；响应 content-type 记录为文档要素；业务 code 位置探测（`.code` / `.err_no` 等），探测不到如实缺省 |
| 调用形态 | 各形态的入参指纹与差异字段可追溯（经关系行与样本层） |
| 诚实边界 | 截断、未验证、单形态等不确定状态必须显式标记，不伪造完整 |

## 8. 非功能性需求

| 类别 | 需求 |
|---|---|
| 存储 | SQLite 单文件（WAL 模式），无外部数据库服务；单文件+目录即可迁移 |
| 规模 | 中小站点为度：50 页/次、单响应 256KB、单样本预览 512B；超限一律诚实标注，不假装成功 |
| 性能 | 采集是长任务，必须后台 job 化；状态查询只认盘、幂等可轮询 |
| 可靠性 | 事件即写即落盘，进程中断后留痕可查；坏数据不炸库（逐条容错） |
| 安全 | 凭证零外传（FR-5.2/5.3）；目标站默认按生产从严对待 |
| 可测试 | 除 e2e 门外全部测试零真浏览器、零 LLM（adapter 注入 fake）；e2e 需 `CAPTURE_E2E=1` 显式开启 |

## 9. 安全与合规红线（反目标）

1. **不做探测式写操作**：永不为了"采接口"自动点提交/删除/审批类按钮；写操作只经 `action` 任务制 + 用户显式确认发生。
2. **不做凭证外传**：cookie/token 值只存本地 SQLite，不进日志、不进工具回执、不出面板路由。
3. **不静默截断**：遇超多页面/超慢站点/超限响应如实回报边界（truncated/notice），不悄悄少采假装成功。

## 10. 本期边界（Out of Scope）

- 交互式探测（自动找按钮点出深层接口）——后期
- 编排 DAG / 探索执行 / 结晶 / 复跑——后期
- 项目维度（采集包 → 项目接口库导入）——后期，但数据模型不与其冲突
- SSO/验证码/双因素攻坚——诚实边界，遇之如实失败
- 万级页面爬行调度——超规模按诚实截断处理
