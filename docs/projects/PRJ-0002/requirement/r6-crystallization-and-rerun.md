## 1. 背景与业务定位

整条流水线的价值终点——"一次探索，次次复跑"。用户的核心场景（原话）："我要 a 材料、b 材料，是这次流程的单子，下一次 c 材料、d 材料，还能跑通吗"。答案是：**能，前提是结晶把每个值分对了类**。

**一句话业务定义**：结晶把首跑确认的值三分类沉淀回链文件（常量冻进节点 / 用户入参冻成槽位 / 链生成值只留求解路径），链升级为可复跑资产；复跑代入新入参、重新求解全部链生成值、无人值守直跑。

**铁律**：响应值只能标为链生成值并保留求解路径，**永不当常量冻结**——工具/schema 层面就不提供这条路径。冻错了（把首跑查出的材料内部 ID 当常量），换入参复跑必挂。

## 2. 业务目标与价值

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 换入参复跑跑通 | A/B 首跑结晶 → 仅换 C/D 复跑 → 成功 |
| G2 | 链生成值重新求解而非回放 | 复跑所得内部 ID/价格 = 代入新入参重新查出来的（断言 ≠ 首跑值时也能成立） |
| G3 | 无人值守 | 复跑全程无 agent 在环、无浏览器 |
| G4 | 失败可诊断 | 复跑失败出报告：哪个节点、哪个值、求解路径哪一环断了 |

## 3. 三分类定义（结晶的分类学）

| 分类 | 定义 | 例子 | 复跑时的处理 |
|---|---|---|---|
| 常量 | 业务固定值 | 采购组织、工厂、URL 固定段 | 冻进节点，原样使用 |
| 用户入参 | 每单可换、人给的值 | 材料编码、数量、要货日期 | 冻成链的入参槽位，复跑时替换 |
| 链生成值 | 上游响应里来的值 | 材料内部 ID、含税价、库存 | **绝不冻结**，代入新入参沿绑定边重新求解 |

`agent-inferred` 来源的值必须经用户确认才能结晶为入参或常量——agent 猜的值不直接变成资产。

## 4. 使用场景

1. **S1 结晶**：A/B 首跑成功 → 系统按来源标注给出分类建议（A/B→入参槽位、内部 ID→链生成值、采购组织→常量）→ 用户确认 → 写回链文件，链标记为"可复跑"。
2. **S2 换入参复跑（C/D 单）**：用户只填材料入参 C、D → 无人值守直跑 → 材料查询接口用 C/D 重新查出内部 ID → 建订单成功。
3. **S3 无效入参诚实失败**：C 不存在或不属于该采购组织 → 链生成值求解失败 → 诊断报告定位到"材料查询→建订单"那条绑定边，如实失败。
4. **S4 漂移适应**：价格/库存以复跑时新查到的为准（这正是不冻结的原因）。

## 5. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-6.1 | 结晶建议：按首跑来源标注自动给出三分类草案（`upstream`→链生成值、`user`→入参候选、卡模板常量→常量） | P0 |
| FR-6.2 | 用户确认闸：分类草案（尤其 `agent-inferred` 的值）经用户确认后才写回链文件 | P0 |
| FR-6.3 | 铁律强制：结晶工具/schema 不提供"响应值冻为常量"的路径 | P0 |
| FR-6.4 | 入参槽位：结晶后链文件含链级 inputs 声明（名称/类型/必填/本次值作示例） | P0 |
| FR-6.5 | 无人值守复跑：代入新入参 → 沿绑定边重新求解全部链生成值 → 直跑（走 R-3 引擎 + R-4 换票） | P0 |
| FR-6.6 | 诊断报告：复跑失败时指出失败节点、涉及值、求解路径断点 | P0 |
| FR-6.7 | 复跑留痕：每次复跑完整落运行记录，与首跑记录可对照 | P1 |

## 6. 验收判据

- **A/B→C/D 端到端**：A、B 材料首跑并结晶 → 仅替换材料入参为 C、D 复跑 → 跑通；且材料内部 ID、价格等链生成值是重新查出来的（与首跑值比对有证据），不是沿用缓存；
- 铁律强制生效：尝试把响应值结晶为常量被拒绝（工具层测试）；
- C/D 无效（不存在或不属于该采购组织）→ 复跑诚实失败，诊断报告定位到求解失败的绑定边；
- 价格/库存类漂移值以复跑时新查到的为准；
- 复跑全程无 agent 在环、无浏览器进程；
- 登录态过期的复跑经 R-4 自动换票后跑通。

## 7. 依赖与不做

- **依赖**：R-5 来源标注质量（标错 → 分错 → 复跑挂）；R-3/R-4 执行与换票；假设"链生成值求解路径在入参变化后稳定"（响应结构漂移时靠半自我修复，超限诚实失败）。
- **不做**：定时/批量调度（开放问题 Q1）；条件边分支（延期）；复跑失败的自动修复超过 R-5 半自我修复范畴的部分。
