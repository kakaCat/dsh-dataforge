- 项目：PRJ-0002 链工坊（接口测试流水线）· 第二期——探索执行
- 需求编号：R-5（6 条拆分需求之一）
- 版本：v1.0（2026-10-17）
- 状态：draft
- 关联需求：R-3 执行引擎（执行能力）、R-4 凭证注入（真实链多有登录态）；本需求的运行记录是 R-6 结晶的唯一原料
- 关联文档：[PRJ-0001 设计 spec](../../../superpowers/specs/2026-10-17-interface-capture-design.md)（"探索执行：快链优先、半自我修复"）

## 1. 背景与业务定位

链第一次跑通常缺参数、缺绑定：用户只知道"我要 a 材料、b 材料，下一张采购单"，不知道材料内部 ID、价格从哪个接口来。纯机器跑不通，纯人工又失去自动化意义——探索执行 = **agent 在环的首跑**，把链从"定义态"推到"跑通态"。

**一句话业务定义**：agent 驾驶执行引擎完成链的首次跑通——试探缺失参数、向用户问关键业务值、失败时分析响应做有限重试与半自我修复；全程每个取值标注来源，落盘为结晶原料。

## 2. 业务目标与价值

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 参数不全的链也能首跑成功 | 只给流程目标（"用 A、B 材料下单"）→ 首跑打通 |
| G2 | 每个值有出处 | 运行记录中每个入参带来源标注与依据 |
| G3 | 失败诚实 | 试探失败如实记录并换值重试，不静默伪造成功 |
| G4 | 产出可直接结晶 | 首跑记录含 R-6 所需的全部信息（值、来源、绑定证据） |

## 3. 角色与使用场景

| 角色 | 说明 |
|---|---|
| agent（AI） | 驾驶者：读接口卡文档、试探取值、问人、分析失败 |
| 用户（人） | 回答关键业务值（材料编码、数量等）；确认 agent 推断的重要取值 |
| 执行引擎 | 被驾驶：按 agent 指令跑节点，如实返回结果 |

**典型场景（用户原话场景的首跑半）**：

1. **S1 首跑 A/B 单**：用户说"用 A、B 两种材料下采购单"→ agent 发现"建订单"节点缺 `materialId` → 读接口库发现材料查询接口 → 补绑定（`materialId` ← 查询出参 `internalId`）→ 用 A 试查询 → 取到内部 ID → 跑通全链。材料编码 A/B 标 `user`，内部 ID 标 `upstream`。
2. **S2 试探失败换值**：材料编码 "A" 查询无结果 → 如实记录 → 向用户确认正确编码 → 换值重试成功。
3. **S3 半自我修复**：某接口 415 → agent 对照卡模板发现 content-type 不符 → 修正重放成功，修复过程落记录。

## 4. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1 | 缺参暂停：引擎跑到缺入参/未定义绑定的节点停下，向 agent 报告"缺什么、卡模板长什么样" | P0 |
| FR-5.2 | 值来源标注：`user`（人给的）/ `agent-inferred`（agent 猜的，附推断依据）/ `upstream`（上游响应来的，附绑定证据）/ `constant`（卡模板常量）——每个入参必填 | P0 |
| FR-5.3 | 绑定发现：首跑中 agent 新建立的绑定边回写链文件（经 R-1 校验） | P0 |
| FR-5.4 | 有限重试与半自我修复：失败时分析响应（状态码/错误体），允许有记数的修正重试；超次数诚实失败 | P0 |
| FR-5.5 | 用户交互闸：关键业务值与写操作节点（如真实下单）首跑确认权属用户 | P0 |
| FR-5.6 | 首跑记录落盘：值 + 来源 + 依据 + 每步请求/响应摘要，即写即落盘 | P0 |

## 5. 验收判据

- 一条参数不全的链（只给流程目标，未给材料编码等）在 agent 辅助下首跑成功；
- 运行记录中每个节点每个入参都有来源标注，`agent-inferred` 的值带推断依据、`upstream` 的值带绑定证据；
- 试探失败（材料编码不存在）如实记录并换值重试，记录中失败尝试可见；
- 首跑中新建的绑定边通过 R-1 校验回写链文件；
- 写操作节点首跑前经过用户显式确认。

## 6. 依赖与不做

- **依赖**：R-3（执行能力）、R-4（真实业务链多有登录态）、R-1（绑定回写校验）。
- **不做**：结晶分类与回冻（R-6——首跑只负责"标注来源"，分类沉淀是结晶的动作）；无人值守执行（R-6 复跑）。
