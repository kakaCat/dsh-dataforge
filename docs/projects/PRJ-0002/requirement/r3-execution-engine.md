## 1. 背景与业务定位

整条流水线从"文档"变"能跑"的分水岭。采集期立下的边界：**浏览器只在采集段使用**——执行段拿接口卡模板直接发 HTTP。本需求交付这条"无浏览器执行路径"的零到一。

**一句话业务定义**：拿链文件做拓扑排序，逐节点纯 HTTP 直调，绑定边自动从上游响应取值喂下游入参，成败如实落运行记录。

**边界**：不含凭证注入与 401 换票（R-4）；本期用无登录态接口链验收。

## 2. 业务目标与价值

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 链不靠浏览器跑通 | 执行全程无浏览器进程启动 |
| G2 | 绑定即依赖真正生效 | 上游出参按绑定边正确传入下游入参，断言值一致 |
| G3 | 调度正确且高效 | 拓扑序正确；并行分支并发；依赖未满足不提前发请求 |
| G4 | 失败诚实可诊断 | 节点 4xx/5xx/超时 → 链中止，运行记录指到失败节点与响应 |

## 3. 角色与使用场景

| 角色 | 说明 |
|---|---|
| 执行引擎（插件进程内） | 无智能执行体：拓扑调度、构造请求、绑定求值、落记录 |
| agent / 用户 | 发起执行、读回运行记录 |

**典型场景**：

1. **S1 直跑无登录态链**：3 节点链（查询→查询→写入类只读验证），上游出参逐级传递，全绿。
2. **S2 并行分支**：链中两个无依赖查询节点并发执行，总耗时 ≈ 较慢者而非求和。
3. **S3 中途失败**：某节点 500 → 链中止，运行记录含失败节点、状态码、响应摘要；已跑节点结果保留可查。

## 4. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 拓扑调度：按绑定边排出执行序；无依赖节点可并发；环在 R-1 已被拒，引擎遇环仍兜底报错 | P0 |
| FR-3.2 | 请求构造：按接口卡 URL 模板 + 入参字段模板拼 query/body/header；缺必填入参即停并标注缺什么 | P0 |
| FR-3.3 | 绑定求值：从上游响应体按声明路径取出参，类型不符/路径不存在如实报错 | P0 |
| FR-3.4 | 运行记录：运行挂在链下（链详情·运行 tab）；每节点记请求/响应摘要/耗时/状态；即写即落盘（沿用 runs 纪律） | P0 |
| FR-3.5 | 失败语义：节点失败默认中止链；节点级重试/超时配置消费 R-1 预留位 | P1 |
| FR-3.6 | 执行可走宿主后台 job（长链不阻塞对话），状态可轮询、可取消 | P1 |

## 5. 验收判据

- 一条 ≥3 节点、含绑定边的无登录态链直跑成功，上游出参正确传入下游（断言传递值与上游响应一致）；
- 并行分支并发执行；依赖未满足的节点不提前发请求；
- 某节点 4xx/5xx/超时 → 链中止，运行记录诚实标注失败节点与响应摘要；
- 绑定路径不存在/类型不符 → 明确报错指到绑定边；
- 全程无浏览器进程启动（进程列表断言）。

## 6. 依赖与不做

- **依赖**：R-1 链契约；假设"接口卡出入参模板足以构造合法请求"（若证伪，本需求范围需重评）。
- **不做**：凭证注入/401 换票（R-4）；agent 在环试探（R-5）；入参槽位替换之外的任何结晶语义（R-6）；条件边（延期）。
