## 1. 背景与业务定位

R-1 的链文件对 agent 友好，但业务用户不会手写 YAML。画布是链的可视化编辑器，原型已定型：网站 → 编排类型（页面编排/接口编排）→ 流程 → 版本 → 编排图三级列表，React Flow 画布上做节点/边编辑。

**一句话业务定义**：用户在面板画布上从接口库拖节点、连线即建立绑定、右侧改属性，保存即得到合法链文件。

**铁律**：画布只是链文件的编辑器——图与磁盘文件**双向一致**，不存在"画布里有而文件里没有"的状态。

## 2. 业务目标与价值

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 不懂 YAML 的用户能编排 DAG | 用户全程不碰文本完成一条链的创建与编辑 |
| G2 | 画布与链文件双向一致 | 画布保存→重开一致；手改文件→画布正确回显 |
| G3 | 画布产物可直接执行 | 保存的链文件通过 R-1 校验、被 R-3 消费 |

## 3. 使用场景

1. **S1 可视化编排**：用户在「编排」标签页选网站 → 选接口编排 → 新建流程 → 画布上从接口库拖入"查材料/查价格/建订单"三张卡 → 连线绑定 → 保存为 v1。
2. **S2 改图**：打开已有编排图，拖点连线、改属性、Delete 删节点，另存 v2。
3. **S3 导入导出**：导出 YAML 归档/分享；导入他人链文件上画布继续编辑。

## 4. 功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 侧栏新增「编排」标签页：网站 → 编排类型 → 流程 → 版本 → 编排图三级列表（按原型） | P0 |
| FR-2.2 | React Flow 画布：从接口库面板拖入节点、拖点连线、点选改属性、Delete 删除 | P0 |
| FR-2.3 | 连线即绑定：连线后在边属性里选择"下游入参字段 ← 上游出参字段"（下拉自卡模板） | P0 |
| FR-2.4 | 保存 = 写 R-1 链文件 + 版本快照；校验失败的图不允许保存（错误指到节点/边） | P0 |
| FR-2.5 | 导入导出 YAML（原型占位按钮转正） | P1 |
| FR-2.6 | 链级入参槽位编辑（对应 FR-1.7） | P1 |

## 5. 验收判据

- 画布操作（增删节点/连线/改属性）保存后重新打开完全一致；
- 画布保存的产物通过 R-1 全部校验，可被 R-3 直接消费；
- 手工修改链文件后，画布打开回显正确（含绑定边字段映射）；
- 成环/悬空等坏图在保存时被拒并指到具体元素。

## 6. 依赖与不做

- **依赖**：R-1 链契约（格式、校验、版本；**页面编排已决编译为接口编排执行**——画布需支持两种类型的编辑，但页面编排保存时产出的是可编译的中间形态）；一期面板骨架（标签页与路由模式沿用采集面板）。
- **不做**：执行与运行视图（R-3 的链详情·运行 tab）。
